# 足球球员表现可视化预测系统 —— 项目体检报告

> 体检范围：Spring Boot 后端（4 个 Java 文件）+ Vue 3 前端（7 个视图 / 11 个源文件）
> 体检方式：全量源码静态审查 + 前端生产构建实测
> 体检时间：本次会话
> 未覆盖：Python 分析服务（不在本仓库，`127.0.0.1:5000`，待提供路径后补充）

## 一、总体结论

**架构是清晰的，代码质量在课程设计/毕设里属于中上水平——但"完善"还谈不上。**

三层架构（Vue 3 → Spring Boot 网关 → Python 分析服务）划分合理，接口注释规范，前端每个视图都有加载态和空状态处理，图表用 ECharts 封装成了可复用组件 `BaseChart.vue`。这些都是加分项。

主要问题集中在四个方向：

| 方向 | 严重度 | 一句话概括 |
|---|---|---|
| ① 前端"丑"的根因 | **高** | 脚手架遗留样式 `style.css` 正在破坏整个布局，这是丑的第一元凶，不是配色问题 |
| ② 后端健壮性 | **中高** | Python 服务一旦挂掉/超时，Java 会返回 500 白页，前端只提示"网络错误"，真实故障被完全掩盖 |
| ③ 前端体验缺口 | **中** | 详情页切换球员不刷新、无 404 页、错误全部静默吞掉、表格排序与后端排序打架 |
| ④ 前端性能 | **中** | 单个 JS chunk 达 1.1 MB（ECharts 全量 + Element Plus 全量引入），首屏白屏明显 |

另外有一个**功能性硬伤**：后端 `/api/similar` 接口没有任何前端页面调用，是一个"通了但没人用"的接口。

## 三、后端问题清单（`src/main/java`）

### B1【高】Python 服务不可用时，错误处理失效

`PythonApiClient.java` 只捕获了 `HttpStatusCodeException`（Python 返回 4xx/5xx 的情况），**没有捕获连接失败和超时**：

```java
try {
    return restTemplate.getForObject(uri, String.class);
} catch (HttpStatusCodeException e) {
    return e.getResponseBodyAsString();
}
// ← ResourceAccessException（服务没启动 / 端口占用 / 连接被拒）
// ← SocketTimeoutException（Python 处理超时）
// 这两个异常会直接穿透到 Spring，变成 500 白页
```

**后果**：现在开发时如果忘了先启动 Flask，前端收到的是 Spring 默认错误页（HTML），`request.js` 解析失败，用户只看到"网络错误或服务未启动"——**排查不出到底是哪一层挂了**。

**修复**：加 `@RestControllerAdvice` 全局异常处理器 + 捕获 `ResourceAccessException`，返回统一 JSON：
```json
{ "code": 503, "message": "分析服务暂时不可用，请稍后重试", "data": null }
```

### B2【高】`RestTemplate` 没有连接/读取超时

```java
private final RestTemplate restTemplate = new RestTemplate();  // 默认无超时 = 无限等待
```

Python 端某个聚类/PCA 接口如果耗时 30 秒，Java 线程会一直挂着，并发几个请求就耗尽 Tomcat 线程池，**整个后端假死**。

**修复**：配置超时（如连接 3s / 读取 30s）：
```java
new RestTemplateBuilder()
    .connectTimeout(Duration.ofSeconds(3))
    .readTimeout(Duration.ofSeconds(30))
    .build();
```

### B3【中】`BASE_URL` 硬编码在 Java 常量里

```java
private static final String BASE_URL = "http://127.0.0.1:5000";
```

换部署机器、改端口、上 Docker 都必须改代码重新编译。

**修复**：挪到 `application.properties`：
```properties
python.api.base-url=http://127.0.0.1:5000
python.api.connect-timeout=3s
python.api.read-timeout=30s
```
用 `@Value("${python.api.base-url}")` 注入。

顺带一提：`application.properties` 目前**只有一行** `spring.application.name=socker`，什么都没配。

### B4【中】所有接口返回裸 `String`，Content-Type 不受控

```java
@GetMapping("/players")
public String players(@RequestParam Map<String, String> params) {
    return client.get("/api/players", params);   // 返回 String
}
```

Spring 对 `String` 返回值默认用 `StringHttpMessageConverter`，可能协商出 `text/plain;charset=ISO-8859-1`。虽然实际因为透传的是 JSON 文本、浏览器/axios 通常能容错，但这是**隐性地雷**——一旦 Python 返回的中文球员名（如 `Mbappé`、中文名）出现乱码，就是这里。

**修复**：改用 `ResponseEntity<String>` 并显式声明：
```java
return ResponseEntity.ok()
        .contentType(MediaType.APPLICATION_JSON)
        .body(body);
```

### B5【中】CORS 配置过于宽松

```java
.allowedOriginPatterns("*")   // 允许任何来源
.allowCredentials(true)       // 同时允许携带凭证
```

开发阶段没问题，但这是**上线即漏洞**的组合。

**修复**：改成从配置读取白名单 `allowed-origins=http://localhost:5173`。

### B6【低】`RestTemplate` 在 Spring Boot 4 中已是老旧 API

项目用的是 Spring Boot **4.1.1**（相当新），但仍在用 `RestTemplate`。Spring 官方推荐用 `RestClient`（3.2+ 引入，流式 API、更好测试）。

**修复**（可选，非必须）：迁移到 `RestClient`。

### B7【低】测试形同虚设

`SockerApplicationTests.java` 只有一个空的 `contextLoads()`。没有任何接口测试、转发测试、异常分支测试。

### B8【信息】`pom.xml` 里的空标签已经查清

`<name/>`、`<description/>`、`<licenses><license/></licenses>` 这些空标签**不是手误**——`HELP.md` 第 18-23 行明确说明：这是 Spring Initializr 为了**阻断从 parent 继承** license/developers 而故意生成的空覆盖。

**但 `<name/>` 和 `<description/>` 仍然建议填上**，因为它们不是被 parent 强制的，空着会让 IDE 和 `mvn` 输出很难看：
```xml
<name>socker</name>
<description>足球球员表现可视化预测系统</description>
```

### B9【信息】前端构建产物没有被 Spring Boot 托管

`socker-frontend/dist/` 存在（构建成功），但 **Spring Boot 不会把它当静态资源**。默认静态目录是 `src/main/resources/static/`。

**后果**：现在只能靠 Vite dev server（5173 端口）访问，无法打成一个 jar 直接部署。答辩时如果只跑 jar 包，前端页面是打不开的。

**修复（三选一）**：
1. 前端构建输出改到 `../src/main/resources/static`（改 `vite.config.js` 的 `build.outDir`）
2. 用 `frontend-maven-plugin` 在 Maven 构建时自动构建前端并拷贝
3. 生产用 Nginx 托管静态文件，反向代理 `/api`

推荐方案 1（最简单，答辩最省事）。

## 四、前端问题清单（`socker-frontend/src`）

### 🎯 F1【高｜UI 丑的根因】脚手架残留样式正在破坏布局

**这是"太丑了"的第一元凶，必须最先修。**

`src/style.css` 是 Vite 脚手架模板残留的 demo 样式，里面有一堆针对**脚手架欢迎页**的规则，却全局生效，直接压在 Element Plus 的布局上：

```css
#app {
  width: 1126px;          /* ← 整个应用被锁死最大 1126px 宽 */
  max-width: 100%;
  margin: 0 auto;
  text-align: center;     /* ← 全局文字居中！表格、表单全被居中 */
  border-inline: 1px solid var(--border);   /* ← 左右各一条竖线，非常怪 */
  min-height: 100svh;
  display: flex;
  flex-direction: column;
}
```

而 `App.vue` 的 `.layout { height: 100vh }` 是撑满全屏的布局——**两者直接冲突**：`el-container` 想撑满，`#app` 却把它压在 1126px 宽并居中，还加了两条边框。

同一个文件里还有一整套**完全没被使用**的样式：`.hero`、`#next-steps`、`#docs`、`#spacer`、`.ticks`、`.counter`、`#social .button-icon`——都是脚手架 demo 的。

而且它定义的变量（`--accent: #aa3bff` 紫色）**没有一个在业务代码里被用到**，业务代码里全是硬编码的 `#1a73e8`。

**修复**：整个文件删掉重写，只保留 CSS reset + 全局字体 + Element Plus 主题变量覆盖。

### F2【高】详情页切换球员不会刷新

`PlayerDetailView.vue` 只在 `onMounted` 里取数：

```js
const playerName = decodeURIComponent(route.params.name)   // ← 只算一次，不是 computed
onMounted(async () => { /* 取数 */ })
```

路由 `/players/:name` 前后是**同一个组件实例**，Vue 会复用它。所以：

1. 你打开"姆巴佩"详情页
2. 点相似球员推荐里的"哈兰德"
3. **URL 变了，页面数据完全不变**，还是姆巴佩的

这是个**用户一用就能发现的真 Bug**。

**修复**：`playerName` 改成 `computed(() => decodeURIComponent(route.params.name))`，然后 `watch(playerName, load, { immediate: true })`。

### F3【高】错误全部被静默吞掉，用户看不到任何反馈

7 个视图里几乎每个请求都是这个模式：

```js
try {
  data.value = await request.get('/xxx')
} catch (e) {
  console.error(e)      // ← 只有控制台，页面上什么都不显示
} finally {
  loading.value = false
}
```

**后果**：Python 服务没启动时，页面转完圈就是一片空白，用户完全不知道发生了什么，以为是页面坏了。只有 `PredictView.vue` 用了 `ElMessage.error`。

**修复**：统一封装 `ElMessage.error(e.message)`，或在 `request.js` 拦截器里全局弹一次。

### F4【高】`.toFixed()` 无空值保护，数据缺失会直接崩

```js
// PlayersView.vue:140
{{ row.Best_Score?.toFixed(1) }}          // ← 这个用了 ?. 是对的
// DashboardView.vue:98
{{ p.score.toFixed(1) }}                  // ← 没有保护，score 为 null 直接 TypeError
// RankingsView.vue:133
{{ row.score.toFixed(2) }}                // ← 没有保护
// ClustersView.vue:210
{{ row.score.toFixed(2) }}                // ← 没有保护
// ClustersView.vue:61 (tooltip 里)
`综合评分：${member.score.toFixed(2)}`     // ← 没有保护
```

一旦某个球员的评分为 `null`（数据缺失、模型未覆盖该球员），整个表格/图表渲染直接抛异常。**项目里 5 处有风险，只有 1 处做了保护**。

**修复**：抽一个 `formatScore(v)` 工具函数统一处理。

### F5【中】表格排序和后端排序打架

`PlayersView.vue` 已经把排序交给后端（`query.order` + `query.direction`），但 `el-table` 的列上又写了 `sortable`：

```html
<el-table-column prop="Age" label="年龄" width="70" sortable />
<el-table-column prop="Best_Score" label="综合评分" width="100" sortable>
```

Element Plus 的 `sortable` 是**纯前端排序，只排当前这一页的 20 条数据**。用户点"综合评分"列头，看到的是"第 1 页 20 个人里排序"，而不是全库排序——**结果完全是错的，而且没有任何提示**。

`RankingsView.vue` 更严重：
```html
<el-table-column label="综合评分" sortable :sort-by="'score'">
```
`el-table-column` 没有 `prop`，`:sort-by` 指向的 `score` 又和渲染用的 `row.score.toFixed(2)` 不是同一个值，排序行为不可预期。

**修复**：要么去掉 `sortable`（推荐，统一走后端），要么加 `sortable="custom"` 监听 `@sort-change` 去调后端。

### F6【中】分页组件缺"每页条数"选择器

```html
<el-pagination
  :page-size="query.page_size"          <!-- 只读绑定，改不了 -->
  layout="total, prev, pager, next"     <!-- 没有 sizes -->
/>
```

`query.page_size` 是 `ref` 里的固定值 20，界面上**无法切换每页条数**。但后端接口是支持 `page_size` 参数的（注释里写了）。

**修复**：`v-model:page-size` + `layout="total, sizes, prev, pager, next, jumper"`。

### F7【中】没有 404 页面

`router/index.js` 没有 `path: '/:pathMatch(.*)*'` 兜底路由。随便输个错误地址，Vue Router 会警告并且 **`<router-view>` 渲染空白**，用户看到一片白。

### F8【中】`document.title` 从不更新

路由里写了 `meta: { title: '数据仪表盘' }`，但**从头到尾没有任何地方使用它**。浏览器标签页永远显示 `socker-frontend`（`index.html:7` 也是脚手架的默认标题，连 `lang="en"` 都没改）。

**修复**：加一个 `router.afterEach` 守卫；`index.html` 改成 `lang="zh-CN"` + 正确的 title。

### F9【中】`request.js` 的错误信息被丢掉

```js
(error) => {
  return Promise.reject(new Error('网络错误或服务未启动'))   // ← 原始错误信息被丢弃
}
```

不管是 404、500、超时还是网络断开，用户看到的**永远是同一句话**。而且没有区分 HTTP 状态码、没有超时专门提示。

另外 `baseURL: '/api'` 意味着**生产环境必须同源部署**（要么 Nginx 反代，要么 Spring 托管静态资源——见 B9）。目前没有环境变量或 `.env` 来切换。

### F10【中】`/api/similar` 接口前端完全没用

后端 `ApiController.java:53` 提供了 `/api/similar`，但**前端 7 个视图里没有任何一处调用它**。详情页的"相似球员推荐"用的是 `/api/players/{name}` 返回里内嵌的 `similar_players` 字段。

**这是一个明显的功能缺口**——要么补一个"相似球员探索"页面（可以做成很出彩的图：输入一个球员 → 力导向图/相似度网络），要么这个接口就是死代码。

### F11【中】图表与样式全部硬编码，没有主题系统

- **颜色散落各处**：`#409eff`（Element Plus 蓝）、`#1a73e8`（Google 蓝）、`#f56c6c`、`#67c23a`、`#909399`、`#606266`、`#5470c6`、`#91cc75`……
  **同一屏里同时出现 `#409eff` 和 `#1a73e8` 两种蓝**（`PlayerDetailView.vue:133` vs `:162`），这是"看起来不专业"的直接原因之一。
- **ECharts 配色各自为政**：`ClustersView.vue` 自己定义了 8 色 `palette`，其他视图又各自写 `#409eff`，**没有统一的图表主题**。
- **ECharts 未适配深色**：所有图表用默认浅色轴线和文字，一旦做深色大屏，图表会瞎掉。

**修复**：建一个 `src/theme/` 目录，集中管理设计 token（色板、间距、字号、圆角、阴影）+ 一个 ECharts 主题对象。

### F12【中】深色模式是坏的

`style.css:33` 写了 `@media (prefers-color-scheme: dark)`，当**用户系统是深色模式**时，它会把页面背景改成 `#16171d`（近黑），但**没有引入 Element Plus 的深色主题 CSS**（`element-plus/theme-chalk/dark/css-vars.css`），也没给 `<html>` 加 `dark` class。

**后果**：深色模式用户的页面变成"深色背景 + 浅色 Element Plus 组件"的诡异混搭。这是个**只在部分用户机器上出现的隐性 Bug**。

### F13【中】响应式缺失

- `App.vue` 侧边栏 `width="200px"` 固定，**不能折叠**
- 所有页面都用 `:span` 固定栅格，**小屏下卡片被压成一条**
- `el-row` 没有配 `:xs` / `:sm` 断点
- 窄屏下侧边栏 200px 会挤掉大半主内容区

### F14【低】其他体验细节

- **`BaseChart.vue` 没有 loading 态**：图表区在数据到达前是纯空白
- **`PredictView.vue` 表单无单位提示**：标题写了"每 90 分钟数据"，但每个输入框没有单位/参考范围，用户不知道该填 0.5 还是 50（**这是预测页最大的可用性问题**）
- **预测结果太单薄**：只有一个 `predicted_score` 大数字，没有"该分数在同位置中处于什么百分位"的对比——而这是预测结果最有价值的信息
- **`CompareView.vue` 跳转后状态不重置**：对比完点球员卡片进详情，再返回，选择器和结果还在，容易误解
- **`loading` 状态混用**：`CompareView.vue` 用同一个 `loading` 同时控制两个下拉框的 `:loading` 和按钮的 `:loading`

### F15【低】`BaseChart.vue` 的 resize 处理不完整

```js
window.addEventListener('resize', resize)
```

监听 `window` 能覆盖窗口缩放，但**覆盖不了容器尺寸变化**（如侧边栏折叠、父容器 flex 重排）。专业做法是用 `ResizeObserver` 监听图表容器本身。

### F16【低】表单交互细节（`PredictView.vue`）

- `el-input-number` 用了 `:controls="false"`，用户**只能手输，不能用鼠标微调**，输入 15 个指标时体验很差
- `label-width="160px"` 固定，**长标签会换行错位**
- `submit()` 里做了 `Number.isNaN` 校验，但**没有校验负数**（出场时间不可能为负）
- 没有"填一个示例球员数据"的一键填充按钮（演示时非常需要）

### F17【低】`RankingsView.vue` 图表 tooltip 的越界风险

```js
formatter: (params) => {
  const p = top10[params[0].dataIndex]    // ← 依赖 series 顺序，且未判空
  return `${p.player}<br/>...`
}
```
`params[0]` 和 `p` 都没做空值保护。

### P1【中】ECharts 全量引入

```js
import * as echarts from 'echarts'   // BaseChart.vue:3 ← 引入全部图表类型
```

项目实际只用了 **5 种图**：`pie`（仪表盘）、`bar`（仪表盘/排行榜）、`radar`（详情/对比）、`scatter`（聚类）。按需引入可把 1.1 MB 砍到 200-300 kB：

